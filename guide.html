Overview

A community speed radar event documents how fast drivers are actually traveling on streets your chapter cares about. Volunteers log readings with a mobile tracker; after the event, you publish a public results page to share with your chapter, neighbors, and local officials.

  1. 1 Before — set up the Google Sheet, tracker site, and volunteers
  2. 2 During — log speeds on priority streets
  3. 3 After — export data, publish the results page, and share findings

One-time setup

Chapter organizers complete this once before the first event. Full technical steps with troubleshooting are in README.md in the project repository.

  1. Google Sheet + Apps Script — create a sheet, paste google-apps-script/Code.gs, deploy as a web app (Execute as Me, access Anyone), and copy the deployment URL.
  2. Configure the tracker — in app.js, set SCRIPT_URL and SECRET to match your Apps Script deployment.
  3. GitHub Pages — push the repo and enable Pages on the main branch (root folder).
  4. Optional branding — add logo.png and set your chapter name in data/manifest.json.
Verify before volunteers use the site Open your Apps Script URL in a private/incognito window with a test reading. You should see {"ok":true} without a Google sign-in page. If sign-in is required, redeploy with the correct access settings.

Plan the session

Do this a few days before each event.

  • Pick 2–5 streets where speeding is a known concern.
  • Agree on a speed threshold for the results page (default 50 km/h; use 40 for residential-focused events).
  • Assign volunteers with radar guns or phone apps that display vehicle speed.
  • Share the tracker URL (index.html on your site) and the event password with volunteers. The password is set in app.js — your chapter lead distributes it; do not post it publicly.
  • Brief volunteers on safety: stay visible, stay on the sidewalk or shoulder, and do not confront drivers. You are observing and recording, not enforcing.

Entering data

Volunteers use the speed tracker on their phones during the event.

  1. Open the tracker link your chapter shared. Enter the event password when prompted. You stay logged in for 7 days on that device.
  2. For each vehicle reading, enter the street name (required).
  3. Tap a direction (N / S / E / W) if it matters for your location — optional; tap again to clear.
  4. Enter speed in km/hr and tap Log speed.
  5. After submitting, the speed field clears but street and direction stay filled so you can log the next vehicle quickly on the same block.
  6. Check Recent readings at the bottom of the page to confirm entries are saving.

Data syncs to your chapter’s shared Google Sheet in near real time. If the connection drops, readings queue on the device and retry automatically.

Tips for a good session

Data quality Use consistent street spelling (e.g. always “Main St”, not “main street”). Record direction when it matters — one-way pairs, uphill vs downhill, or opposite lanes on a wide road.
  • Aim for at least 3 readings per street so that street appears in the results charts and table.
  • Pick a consistent time window (e.g. Saturday morning) so results are comparable month to month.
  • Position volunteers where they can read plates of traffic safely — visible clothing helps.
  • One volunteer per phone is ideal; if phones are shared, note the real volunteer count when publishing (see Publish results).
  • Take a group photo and note which streets you covered — useful for social media and council presentations.

Publish results

After the event, a chapter organizer exports the sheet data and updates the site so the results page goes live.

1. Export CSV from Google Sheets

  1. Open your Google Sheet.
  2. File → Download → Comma Separated Values (.csv)
  3. Save as data/events/<slug>.csv (e.g. data/events/2026-06-june.csv).

2. Update the manifest

Edit data/manifest.json and add an event entry to the events array:

{
  "slug": "2026-06-june",
  "title": "June 2026 Community Speed Radar",
  "description": "What streets you monitored and why — plain language for the public.",
  "date": "2026-06-28",
  "csv": "data/events/2026-06-june.csv",
  "speedThreshold": 50
}

Optional: add "volunteers": 5 when the real headcount differs from unique devices in the CSV (e.g. shared phones).

Field Required Notes
slug Yes URL-safe id, used in results.html?event=slug
title Yes Shown in results header
description Yes Context for readers and council
date Yes ISO date YYYY-MM-DD
csv Yes Path to committed CSV file
speedThreshold No km/h for “% over X” stats; defaults to 50
volunteers No Headcount override; defaults to unique device IDs in CSV

The results page shows the newest event by default.

3. Push to GitHub

git add data/
git commit -m "Publish June 2026 speed radar results"
git push

Results go live at https://<username>.github.io/<repo>/results.html after GitHub Pages deploys (usually within a minute or two).

4. Share

  • Chapter email or social media — link to the results page
  • Local council or traffic committee
  • Monthly meetup discussion

View results

Anyone can open the results page once an organizer has published an event. The page computes stats from your CSV — no manual analysis needed.

Stat What it means
Median speed The middle value — typical driver, not skewed by one outlier
85th percentile Speed at or below which 85% of drivers traveled; familiar to traffic engineers
% over threshold Share of vehicles faster than your speed threshold (default 50 km/h)
Highest recorded Worst single reading — useful as a headline, not the typical speed

The By street section compares locations side by side: median, 85th percentile, and % over threshold for each street. Use the tabs to see speed distributions per street.

Before results are live The results page only shows events listed in data/manifest.json with a committed CSV. During the event, data lives in the Google Sheet; volunteers use the tracker, not the results page.

Presenting to council

When you bring findings to elected officials or staff, lead with:

  1. How many readings and streets — establishes credibility and effort
  2. % over threshold — the problem in one number
  3. Which streets scored worst — where to focus action

Pair the results infographic with a short narrative: why you chose these streets, what residents experience, and what Strong Towns principles suggest (slower speeds, safer design, enforcement as one tool among many).

Shut down

When your chapter is done running speed radar events:

  1. In Apps Script: Deploy → Manage deployments — disable or delete the web app.
  2. Optionally take down GitHub Pages.
  3. Archive or delete the Google Sheet.

The tracker password and script secret are fine for a short community event but should be retired when the event ends. See the README security notes for details.
